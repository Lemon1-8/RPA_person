# 可靠性与长期运行

## Agent 入口与数据目录互斥

Agent CLI 支持直接执行流程文件或代码文件，并保留不可变的流程与固定修订依赖快照；桌面整流程入口仍要求内容匹配已保存修订。详情见 [Agent 使用与分发](Agent使用与分发.md)。

桌面、旧 CLI 和 Agent CLI 的运行管理器在恢复历史前获取按规范化数据目录命名的 Windows 全局互斥锁。同目录的第二个写入者返回 `DATA_DIR_BUSY`；不同目录可独立运行。锁由独立辅助进程持有，正常退出或持有者进程退出后释放，不依赖手动清理残留 PID 文件。历史查询不初始化管理器，不会将正在执行的任务标记为中断。

Agent 入口为单次调用：遇到暂停、人工等待、用户接管、总超时或取消时停止并清理本次会话，保存原始原因与已有产物后返回，不自动确认和重试。没有原浏览器现场恢复能力，重新执行有外部效果的步骤前应核实业务结果。

## 2026-10-13 可靠性修复

浏览器动作的排队、启动、iframe 定位与目标操作共用一个超时期限。普通定位超时后保留已经结束操作的浏览器现场；操作在到期后的收尾等待内仍未结束时，会关闭本次会话，阻止迟到的点击或输入。网页鼠标和键盘指令选择其他标签页时，只影响本步骤，不改变后续指令的当前网页。

人工恢复的检查、确认、重试、跳过及调试单步使用同一套 IPC 命令。恢复检查继承失败时的局部变量值、元素和设置；检查输出显式发布到父级。运行前检查只延迟校验动态值，确定的错误仍阻止启动，包含动态引用的 JSON 中已知类型错误也不会被占位值掩盖。

已有业务进度缺少输入快照或进度日志时，拒绝自动续跑；尚未进入的循环仍可首次执行，旧内联进度格式保持兼容。XLSX 在同目录临时文件中写入完成后再替换目标，写入失败保留旧文件。并发日志分别保存和登记失败项，一个任务写入失败不会丢弃其他任务的待写日志。

运行快照只在待写入或待重试期间缓存，任务进程结束后保留元数据，完整变量按需读取。打开产物或目录只检查元数据，不同步加载全部历史变量。调度启动时恢复未完成领取，后续只追踪未完成项，不再每秒扫描全部触发账本；账本未提交的运行受历史清理保护，提交后再允许清理，避免误判为未执行而重跑。流程 JSON、运行记录和计划格式保持兼容。

## 草稿、修订和日志

草稿与正式保存版本分别存储。编辑停止 1 秒后保存草稿，连续编辑最长每 5 秒刷新；退出程序前等待界面刷新草稿。无效 JSON 字段文字也可恢复。启动后由用户选择恢复或放弃，保存版本冲突时恢复为副本。

保存流程前归档当前修订；恢复历史内容会创建新修订。首次升级从当前保存版本开始，没有对应历史的旧版本不会被虚构。

日志按运行分页读取，每页默认 200 条，支持搜索、加载更早记录和导出 JSONL。旧日志按原记录读取，损坏行显示数量且保留原文件。每次运行尝试保存独立快照。

“忽略失败”仍允许流程完成，但会累计警告并显示“完成但有警告”。成功重试与正常 Catch 不计警告。CLI 成功退出码保持为 0，同时输出警告摘要。

草稿、日志和运行记录写入失败时显示持续提示，修复访问权限或空间后可重试。正式保存失败需用户重新保存，以保留修订冲突检查。

## 长期调度

日历规则支持每周多个日期、每月指定日期及从开始日期起间隔 N 天，使用本机时区。缺少指定日期时按当月最后一天执行。编辑计划可预览未来五次触发时间。新计划默认固定当前保存修订，通过“更新使用版本”明确更新；旧计划缺少修订时仍跟随最新。

只补最近一次可识别的漏跑，活动或等待人工的同流程记录主动跳过。触发账本先持久化领取状态及预分配运行 ID，再创建运行并关联；重启可补齐创建之前的退出窗口，已创建的运行不会再次执行。历史触发信息已丢失时不反推补跑。固定修订缺失时停用计划并提示。

“读取运行信息”指令、JS `rpa.getRunContext()`、Python `rpa.get_run_context()` 返回只读运行上下文，由用户明确保存输出。内置示例使用 `rpa://demo` 地址，在执行时解析本次启动端口；旧固定示例修订也支持原始打开步骤的端口解析，普通用户网址保持原值。
