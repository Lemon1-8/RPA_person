# 可靠性与长期运行

## 草稿、修订和日志

草稿与正式保存版本分别存储。编辑停止 1 秒后保存草稿，连续编辑最长每 5 秒刷新；退出程序前等待界面刷新草稿。无效 JSON 字段文字也可恢复。启动后由用户选择恢复或放弃，保存版本冲突时恢复为副本。

保存流程前归档当前修订；恢复历史内容会创建新修订。首次升级从当前保存版本开始，没有对应历史的旧版本不会被虚构。

日志按运行分页读取，每页默认 200 条，支持搜索、加载更早记录和导出 JSONL。旧日志按原记录读取，损坏行显示数量且保留原文件。每次运行尝试保存独立快照。

“忽略失败”仍允许流程完成，但会累计警告并显示“完成但有警告”。成功重试与正常 Catch 不计警告。CLI 成功退出码保持为 0，同时输出警告摘要。

草稿、日志和运行记录写入失败时显示持续提示，修复访问权限或空间后可重试。正式保存失败需用户重新保存，以保留修订冲突检查。

## 采集与编辑

高级采集与校验指令默认折叠，可展开或通过“高级”分类查找。网页元素库支持在保留会话中拾取、重新验证、高亮和重命名；可选择当前指令及子步骤或整个流程作为保存范围，维护已有的全局元素。重命名更新结构化引用及恢复检查，拒绝被局部同名元素覆盖；脚本原文保留并列出待人工修改位置。拾取会拦截普通业务点击并保存逐层 iframe 定位，取消或页面导航后清理监听。新元素保存后当前指令通过 `@元素名` 使用。

步骤列表提供搜索和批量复制、删除、移动；移动完整子树且禁止移入自身后代，复制同步重建恢复检查项的标识。`Ctrl+S` 保存当前流程。变量可展开查看或预览前 100 行。脚本检查只编译/解析源码，不执行业务代码，不自动安装依赖。

整流程运行前执行参数和环境检查，确定错误阻止启动；运行时引用给出提醒并在执行时再次校验。Python 检查明确使用 UTF-8，兼容 Windows 默认编码与中文源码。

第一阶段：`tests/workbench-store.test.ts` 覆盖草稿、修订、5001 条历史日志、损坏行和保存故障重试；`scripts/smoke-reliability.mjs` 验证真实 Electron 的无效 JSON 草稿恢复和修订记录。

## 调试、恢复与前台让出

每次执行尝试保存独立参数快照。断点在执行前暂停，循环可重复命中；调试暂停可执行下一步。指定顶层步骤作为调试起点需先保留浏览器并准备前置变量。

新增有外部效果的指令默认失败后等待人工决策，可执行配置好的只读检查、确认已完成、明确重新执行或跳过。跳过记录警告；不会凭空生成输出。运行中的草稿修改不改变执行快照。

列表与 XLSX 循环可配置稳定业务键，重复或空键在子步骤执行前拒绝。仅完整成功的业务项记为完成；存在警告或效果未知的项目保留待检查状态。数据续跑创建关联原运行的新记录，重新执行入口准备步骤，未知项目需人工选择；续跑使用原输入快照，原 XLSX 文件被移动或删除也不会改变业务项。普通流程不能自动跳到中间步骤。

前台输入保留跨进程互斥锁，默认等用户空闲 3 秒，资源最长等 15 分钟，均可在流程设置调整。资源等待不占用动作超时。低级键鼠钩子区分注入输入与真实用户输入，用户接管或窗口变化后停止后续输入并释放已按下的键、按钮和锁；人工确认前不自动重放。Ctrl+Alt+F12 停止全部任务，快捷键冲突显示持续提示。粘贴后只在剪贴板仍由程序占用时恢复原内容。

第三阶段行为测试覆盖重复断点、单步、人工决策及 802 项循环在第 800 项失败后续跑；真实 Electron 恢复界面覆盖小窗口布局。真实前台验收需要空闲桌面，外部滚轮会按保护规则中断测试。

## 长期调度

日历规则支持每周多个日期、每月指定日期及从开始日期起间隔 N 天，使用本机时区。缺少指定日期时按当月最后一天执行。编辑计划可预览未来五次触发时间。新计划默认固定当前保存修订，通过“更新使用版本”明确更新；旧计划缺少修订时仍跟随最新。

只补最近一次可识别的漏跑，活动或等待人工的同流程记录主动跳过。触发账本先持久化领取状态及预分配运行 ID，再创建运行并关联；重启可补齐创建之前的退出窗口，已创建的运行不会再次执行。历史触发信息已丢失时不反推补跑。固定修订缺失时停用计划并提示。

“读取运行信息”指令、JS `rpa.getRunContext()`、Python `rpa.get_run_context()` 返回只读运行上下文，由用户明确保存输出。内置示例使用 `rpa://demo` 地址，在执行时解析本次启动端口；旧固定示例修订也支持原始打开步骤的端口解析，普通用户网址保持原值。

第四阶段测试覆盖闰年、月末、每周日期、N 天基准、旧计划兼容、固定修订、领取后退出、防重与 SDK 上下文。`scripts/smoke-schedules.mjs` 验证真实 Electron 的规则预览和两个窗口尺寸。

## 开销、历史与子流程

运行中仅传递变化变量和删除键，终态与主动查询提供完整变量。步骤的大结果独立保存，日志中显示摘要并提供完整结果查询。普通状态和 JSONL 写入最多每 500 毫秒合并，暂停、人工等待和终态立即刷新；业务检查点单独逐项落盘，不参与延迟合并。业务输入只保存一次，后续进度使用追加事件。

日志超过 300 个显示行后按可见窗口渲染，历史首次读取最近 200 条，可持续分页和搜索全部记录，并按执行尝试查看。历史运行按流程、日期、状态与归档标记分页。归档不会删除数据，清理必须先预览再确认；只删除程序记录文件，业务产物和失败截图保留；已登记的 JSON 业务产物即使存放在记录子目录也会排除。最新修订、固定计划及子流程引用的修订受保护。启动先读取历史元数据，完整变量按需读取；界面启动返回最近 50 个运行及全部活动会话。

“调用子流程”必须指定固定修订。流程在设置页声明输入与输出变量名，调用只接受声明的输入，并显式返回声明的输出对象。子流程使用局部变量、元素与脚本环境，共享父流程浏览器；统一遵守暂停、停止和容器超时。启动前拒绝循环调用，执行尝试保存不可变依赖快照。浏览器配置使用父流程设置。

`tests/runtime-optimization.test.ts` 覆盖增量重建、大结果读取、状态合并、真实浏览器共享、固定子流程、循环调用拒绝、超时停止和清理保护。`scripts/smoke-runtime-history.ts` 验证 5,001 条日志的分页、搜索、窗口化及两个窗口尺寸。

## 性能记录（2026-10-12）

`npx tsx scripts/benchmark-runtime.ts before` 与 `after` 使用两个并发执行器、每个 10,000 行、每行三步，结果见 `.rpa/qa/performance-before.json` 与 `performance-after.json`。`before` 在第五阶段改动前执行，`after` 在改动后执行；参数只标记输出记录，不自动回退实现。该对照在同一 Node 进程中执行，计数序列化载荷，避免把重复大快照真正写入磁盘。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 耗时 | 520,009 ms | 2,320 ms |
| 事件载荷 | 7,200,893,163 B | 69,089,024 B |
| 状态保存载荷 | 21,562,575,714 B | 21,880,050 B |
| RSS 峰值 | 237,453,312 B | 270,376,960 B |

两次结果哈希一致。短时高吞吐测试的 RSS 峰值略有增加，不能声称该指标已改善；上述耗时仅代表纯计算流程，真实网站等待仍取决于页面和业务操作。

`after --physical` 另测两个独立任务进程与真实 JSON/JSONL 存储：耗时 12,772 ms，事件载荷 76,348,338 B，状态写入 45 次（载荷 32,343,024 B），最终记录文件共 83,523,922 B。事件保持完整，最终变量哈希与对照一致。文件最终大小与累计写入载荷是不同指标。

## 真实前台验收（2026-10-12）

在用户明确预留的空闲桌面上串行执行 `scripts/smoke-desktop-input.ts`、`scripts/smoke-desktop-point.ts`、`scripts/smoke-windows-elements.ts`，并定向执行 `tests/windows.test.ts` 的真实模拟操作用例，均通过。覆盖真实点击、连续弧线移动（最大偏移 80.5 像素）、中文输入、粘贴与原剪贴板恢复、F8 坐标拾取、软件元素捕获以及 Esc 取消后原配置保留。此前外部滚轮输入触发保护并中止操作，空闲补验期间保持输入监测启用。

捕获验收的快捷键发送使用已预留桌面的零空闲等待配置，避免测试启动开销占用拾取的 30 秒期限；产品默认 3 秒空闲等待保持不变。原生软件模拟操作用例仍使用默认等待策略。
