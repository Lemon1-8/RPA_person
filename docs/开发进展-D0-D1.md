## 当前实现边界

1. **前台仲裁**：采用 CDP 最小化／恢复。未实现 Win32 键鼠空闲检测、窗口前台锁与排队，因此不承诺自动无打扰的前台操作。锁屏、无人登录与开机启动未验收。
2. **复杂控件**：已有选择器、iframe、原生 select、点击及结果校验；可视化拾取器、自定义下拉、日期／级联控件仍需 D2。
3. **有外部效果的失败恢复**：本轮对点击、下载、脚本不自动重试，不提供失败后重新触发。只读动作可重试／暂停并人工恢复。异步导出任务的检查与恢复策略在 D3／站点模板中实现。
4. **持久化和调度**：D1 使用 JSON 与 JSONL，未引入 SQLite；日／周／月／间隔 N 天计划、漏跑补最近一次及计划防重尚未实现。
5. **跨入口管理**：桌面与 CLI 复用运行管理代码及契约，目前各自启动管理器。常驻服务统一入口和本地 API 尚未实现，不能同时共享一个数据目录。
6. **崩溃恢复**：只标记意外中断；浏览器原现场不可恢复。配置目录租约为保守人工清理策略，禁止确认前自动删除。
7. **脚本环境**：需要用户已安装的 Python，依赖不隐式安装。JS/TS 临时模块可使用 Node 内置库和 RPA SDK；加载项目第三方模块应使用 `createRequire` 从项目目录解析。完整脚本项目环境管理尚未提供。
8. **分发**：已提供源码、开发构建与启动脚本，尚未生成 Windows 安装包。
9. **拼多多**：尚未连接或适配真实商家后台；没有拼多多选择器写入通用引擎。下一步需登录后验证 DOM、弹窗、异步下载与浏览器兼容性，保存为独立模板。

## 技术依据

- 桌面使用隔离 renderer 与窄化的 preload API；外部网页留在独立自动化浏览器。[Electron Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)、[Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)。
- 持久化浏览器使用独占配置目录；下载在上下文关闭前保存到目标位置。[Playwright BrowserType](https://playwright.dev/docs/api/class-browsertype)、[Downloads](https://playwright.dev/docs/downloads)。

官方 API 能力与本机受控验收共同作为当前实现依据；真实站点兼容性另行实测。
