# XLSX 与电脑键鼠指令

## XLSX

“读取 XLSX”只解析选中的工作表；工作表名称留空时读取第一个工作表。输出为 `{ sheetName, rows }`，其中 `rows` 是以首行为列名的数据行列表。读取器支持 ZIP64 封装的 `.xlsx` 文件。升级至 SheetJS 0.20.3 后，写入 XLSX 仍生成普通 `.xlsx` 文件；现有流程的动作类型和参数未变。

桌面界面的“读取 XLSX”和“遍历 XLSX”可点击“浏览…”打开系统文件选择窗口；“保存 XLSX”可点击“另存为…”选择保存目录和文件名。选择后完整路径自动填入步骤参数；取消选择保留原路径。路径仍可手动填写，便于使用 `{{变量}}` 生成运行时路径。CLI 和已有流程格式不变。

“遍历 XLSX”直接按文件中的数据行运行循环体，无需先配置“读取 XLSX”和“遍历列表”。新建步骤默认把每一行作为数组放入当前行变量 `row`：`{{row}}[0]` 读取该行第 1 列，`{{row}}[1]` 读取第 2 列；下标从 0 开始，必须紧跟在 `}}` 后面。`{{row}}.0` 会把 `.0` 当作普通文字。第一行作为表头，不参与遍历。单元格保持原始的文本、数字等类型。已有流程未设置遍历模式时仍按整行对象执行，可继续使用 `{{row.列名}}`；在界面切换为“整行数组”即可按下标取值。也保留固定列下标的“单列值”模式。最多遍历 10000 行，循环结束会恢复原来的同名变量。原有“遍历列表”继续处理普通 JSON 列表。

循环体中“打印日志”引用整个 `{{row}}` 时，运行日志将行对象按字段逐项显示，方便查看长列名和空值。日志面板默认隐藏所有指令的执行中、完成耗时和跳过提示，保留实际输出、文件产物、失败信息及运行状态；步骤卡片仍更新执行状态。需要排查执行过程时，可开启日志工具栏的“显示指令执行信息”，或点击“步骤”筛选主动查看，选择会保存在本机。此设置只影响日志显示，不改变流程格式、指令参数和执行事件。任务进程会等待日志和最终运行状态发送完成后再退出，避免读取 XLSX 后的大变量使消息积压，导致漏行或误报意外中断。

“保存 XLSX”的行列表也接受单行对象：填写 `{{row}}` 会生成只有当前行的工作簿；填写对象列表时仍按原来的多行格式保存。

遍历可配置稳定的“续跑业务键模板”。空键或重复键在子步骤执行前拒绝，只有完整成功的行记为完成。通过运行结果中的“检查后建立数据续跑”使用原修订和原输入快照重建执行，原 XLSX 文件后续移动或删除也不会改变续跑业务项；存在警告或效果未知的项目需检查后明确决策。详见 [可靠性与长期运行](可靠性与长期运行.md)。

## 电脑键鼠

“键盘和鼠标操作”分类中的 `desktop.*` 指令向 Windows 当前前台窗口发送真实鼠标和键盘输入，可用于浏览器、办公软件及其他桌面程序。运行时会占用鼠标和键盘；执行前应让目标窗口位于前台，并保持它可见。鼠标坐标以整个屏幕左上角为原点，多显示器左侧或上方的坐标可以为负数。滚轮值以 120 为一格；负的纵向值向下滚动。

真实输入与 Windows UIA 模拟操作共用跨进程交互锁，默认等用户空闲 3 秒，资源最长等 15 分钟，均可在流程设置调整。等待锁和用户空闲不占用动作超时。执行中监测真实用户输入和前台窗口变化，用户接管后停止后续输入并释放按键、按钮和锁；人工确认前不自动重放。Ctrl+Alt+F12 可紧急停止全部任务。

原有 `browser.mouseClick`、`browser.mouseMove`、`browser.mouseWheel`、`browser.keyPress`、`browser.keyboardType` 保留原参数和浏览器内执行行为，现归入“网页操作”。它们使用网页视口坐标，适合不抢占系统鼠标键盘的网页自动化；既有流程无需迁移。浏览器“获取坐标”只适用于这两条网页鼠标指令。

电脑鼠标点击与移动的 X、Y 坐标可手动填写，也可点击“获取屏幕坐标”：将鼠标移到目标位置后按 F8。取点使用整个桌面的物理像素坐标，多显示器左侧或上方可能出现负数。默认开启“真人轨迹”，鼠标沿带随机弯曲方向和幅度的弧线移动，并在起点和终点平缓加减速；关闭后直接定位。网页鼠标指令的取点方式仍为 Ctrl + Alt + 左键单击，使用网页视口坐标。

“按下键盘”提供常用按键选择，也保留自定义快捷键和变量引用。“键盘输入”可选择逐字输入或剪贴板粘贴；粘贴模式临时写入系统剪贴板，结束时仅在剪贴板仍由程序占用的情况下恢复原内容，避免覆盖用户后续复制的内容。勾选“先输错字并删除”后，会先输入配置的错字、逐字退格，再输入或粘贴正确文本。Windows 锁屏、安全桌面或目标程序权限高于运行器时，系统可能拒绝输入。

“网页按下键盘”使用目标网页的自动化会话，默认给按键保留约 70–150 毫秒的按住时间，也可手动设置“按键时长”。它只发送按键到当前网页中已获得焦点的控件。对于需要前台真实键盘输入的页面，可以先让浏览器显示并获得焦点，再使用电脑“按下键盘”指令；这种方式会占用键盘。网站仍可能要求验证，按键时长和输入来源都不能保证免于站点的安全验证。
