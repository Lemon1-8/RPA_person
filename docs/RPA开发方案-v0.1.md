# RPA 开发方案 v0.1

日期：2026-09-15  
状态：2026-09-15 制定的建议方案，保留为历史设计依据；文中的阶段计划与“当前”描述对应制定时，技术选型与默认规则不代表用户逐项确认。项目已进入实现，现有能力、限制和验证入口见 [README](../README.md) 与 [可靠性与长期运行](可靠性与长期运行.md)。

## 1. 开发目标和当前基础

开发 Windows 本地 RPA：纵向步骤式编辑器、后台浏览器执行、可视化与 Python／JS／TS 混合编排、多任务并行、定时计划、自定义下载路径与命名。

已有依据为《RPA产品需求共识-2026-09-15.md》及历史讨论记录。用户进一步明确：实际任务由 RPA 程序执行，不依赖 Agent 逐步操作；后续进入开发设计，不再讨论网站操作教学。

第一个真实业务样本为拼多多商家后台订单导出。当前只有 URL 和截图，未验证真实 DOM、导出弹窗、异步生成机制、登录兼容性；尚未导出文件。真实网站适配与通用引擎分开维护。

## 2. 推荐技术栈

| 部分 | 建议 | 选择理由 |
| --- | --- | --- |
| 桌面应用 | Electron + React + TypeScript | 同一 TypeScript 工程覆盖桌面入口、步骤编辑、运行监控；便于与 Node 执行器共享协议。 |
| 编辑器 | 自定义纵向步骤列表、缩进块、参数面板 | 匹配用户确认的影刀式布局；流程本身保存为结构化数据。 |
| 执行引擎 | Node.js + TypeScript，独立进程 | 统一浏览器、流程、日志、调度；界面刷新不直接打断任务。 |
| 浏览器控制 | Playwright + 独立 Chromium 配置目录 | 提供定位、iframe、响应监听及下载基础；目标网站兼容性由实测确认。 |
| Python 脚本 | Python 子进程 + 本地 RPC SDK | 与可视化、JS／TS 共享当前任务浏览器，避免维护第二套自动化内核。 |
| JS／TS 脚本 | 独立 Node 脚本进程；TS 先转译 | 通过同一 SDK 调用引擎，脚本卡住时可终止脚本进程并保留浏览器。 |
| 数据 | 带版本号的流程 JSON + SQLite | JSON 保存流程与元素定义；SQLite 保存计划、运行状态、步骤事件和产物索引。 |
| Windows 集成 | 小型 C#／Win32 辅助进程 | 只承担键鼠空闲检测、窗口识别与前台切换；浏览器常规操作交给 Playwright。 |
| 外部入口 | CLI、JS／Python SDK；本地 API 分阶段补齐 | 所有入口调用同一执行协议。 |

Electron 的多进程与 utilityProcess 文档说明了界面、主进程和工作进程的分工能力。本方案进一步建议把执行器生命周期与编辑窗口分开管理。[Electron 进程模型](https://github.com/electron/electron/blob/main/docs/tutorial/process-model.md)、[utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)。

具体依赖版本在初始化时选择并锁定兼容组合。

## 3. 核心架构与数据契约

编辑器、CLI 和 SDK 都把请求交给运行管理器。运行管理器启动任务执行进程；任务执行进程独占当前任务的浏览器并执行步骤，脚本通过 RPC 使用它。界面通过事件订阅显示进度。

### 3.1 六个模块

1. **流程模型**：定义步骤、变量、条件、循环、元素引用与版本迁移。
2. **执行器**：解释流程，处理超时、取消、重试、暂停、恢复及事件记录。
3. **浏览器与元素系统**：管理配置目录、标签页、iframe 路径、定位、拾取与控件适配。
4. **脚本桥接**：让 Python 和 JS／TS 使用当前任务的浏览器及变量。
5. **运行管理与调度**：控制并发、同流程互斥、计划触发、补跑、前台排队与产物归属。
6. **桌面编辑器**：编辑流程、配置步骤、管理元素、显示日志和人工恢复入口。

### 3.2 先定义的核心对象

| 对象 | 必须包含的内容 |
| --- | --- |
| WorkflowDefinition | schemaVersion、workflowId、输入变量、元素库、步骤树；运行时引用不可变版本。 |
| StepDefinition | stepId、actionType、参数、输出映射、超时、重试与失败策略。 |
| ActionDefinition | 输入／输出 schema、执行函数、参数界面元数据、重复执行是否安全。 |
| ElementRef | pageRef、逐层 framePath、定位策略、期望匹配数量。 |
| Run | runId、流程版本、状态、scheduledFor、实际开始时间、当前步骤、浏览器配置引用。 |
| StepResult | 输出变量、状态、耗时、错误分类、截图和下载产物引用。 |
| ScheduleOccurrence | scheduleId、scheduledFor、已触发／主动跳过／漏跑处理结果；使用唯一键防重。 |

一份动作定义同时用于参数校验、界面表单和 SDK，减少三处维护时的不一致。条件与循环用步骤树表达，编辑器把它显示为缩进列表。

变量基础类型为 JSON 可表达的文本、数字、布尔、空值、列表和对象；日期约定格式与时区，文件使用路径与元数据。Page、Locator 等原生对象留在浏览器执行进程内，脚本使用 pageId、elementId 等引用。

## 4. 需要在实现初期解决的机制

### 4.1 后台运行和前台恢复

先以有界面的独立浏览器会话验证“不占用用户鼠标键盘”。正常浏览器动作不请求前台；窗口隐藏或最小化方式通过实测选择。需要人工登录、检查现场或明确的前台动作时，申请统一前台使用权，等待用户空闲。

前台切换成功后才执行依赖前台的动作。切换被系统拒绝或用户重新操作时，应等待或暂停，并在界面给出恢复入口。不能把无头浏览器与有界面浏览器的会话切换当成现成能力。

Windows 可通过 GetLastInputInfo 获取当前登录会话的输入空闲信息，但 SetForegroundWindow 存在系统限制；键鼠空闲不保证前台切换一定成功。[GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)、[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

后台运行仍消耗 CPU 和内存。因此需要可配置并发上限，并保留资源占用记录。

### 4.2 浏览器隔离和登录

每个并发浏览器有独立的配置目录租约；禁止两个浏览器同时使用同一个目录。同站点多流程使用同账号时，仍须验证网站是否允许多个登录会话，不能把资料目录隔离当作网站允许并发登录的保证。

Playwright 持久化上下文可保留浏览器会话数据，官方明确同一用户数据目录不能被多个浏览器实例并发使用。[持久化浏览器上下文](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)。

### 4.3 元素与复杂控件

- 拾取结果保存 iframe 路径和目标定位信息；执行时重新定位，遇到多匹配应报告歧义。
- 控件动作按原生下拉、自定义列表、搜索列表、日期／日期范围、级联类目分别适配。
- 弹层可能挂在页面其他容器，入口、选项和结果校验分别配置。
- 动作成功要核对页面结果；点击成功不直接等于业务筛选已经生效。
- 元素拾取器作为独立模块；第一轮使用运行器注入的拾取覆盖层验证 iframe 感知，扩展方案待覆盖能力验证后决定。

以上由 Playwright 的定位器及 FrameLocator 能力支撑，但通用控件识别和业务结果校验需要我们开发。[定位器](https://playwright.dev/docs/locators)、[FrameLocator](https://playwright.dev/docs/api/class-framelocator)。

### 4.4 响应采集与下载

网络监听和下载监听都在触发动作之前建立。响应根据 URL、请求参数、页码或筛选条件进行关联，防止拿到旧请求结果。

导出步骤分开记录“导出任务已发起”和“文件已保存”。异步生成时记录能识别本次任务的信息，恢复后先检查已有结果再决定是否重发。

下载使用每次运行的临时目录，并将文件按目标路径保存；保存成功且可访问后才记录成功。最终输出路径、文件名、大小与来源步骤；并发保存使用独占命名／创建策略避免覆盖。

Playwright 支持网络响应事件和下载事件，下载文件应在关闭浏览器上下文前保存到最终位置。[网络事件](https://playwright.dev/docs/network)、[下载](https://playwright.dev/docs/downloads)。

### 4.5 双语言执行

浏览器只有一个控制所有者。Python／JS／TS 脚本的浏览器请求经 RPC 发回任务执行器，同一任务中的浏览器动作默认顺序处理。脚本进程具备执行超时与取消机制，日志绑定 runId、stepId。

进程分离用于故障与生命周期管理，不应宣传成不可信脚本的安全沙箱。初期运行用户自己编写的本地脚本；第三方依赖由明确的项目环境管理，不能在流程运行时隐式安装。

### 4.6 调度和暂停

状态建议为：准备、运行、等待前台、等待人工、成功、失败、停止、意外中断。

- 同流程在运行、等待前台或等待人工时仍占用执行名额，新计划主动跳过。
- 暂停任务保留浏览器；释放前台使用权，但保留实际占用的浏览器资源额度。
- 每个计划触发结果持久化；停机恢复只补最近一次，主动跳过不补。
- 调度按 scheduledFor 计算业务日期，避免漏跑补执行时查询了错误周期。
- 浏览器仍存活时支持现场恢复；崩溃、重启、断电后标记意外中断，不能宣称能恢复原 DOM 现场。
- 日期推进用可注入时钟进行测试；不要只依赖内存定时器。

初期建议执行器运行在 Windows 用户登录会话中，由托盘入口管理；关闭编辑窗口只收起窗口，明确退出才停止运行器。开机启动、锁屏运行和无人登录运行作为独立能力验证，以上生命周期属于建议。

## 5. 开发顺序与验收

所有阶段属于同一产品的增量交付。把能力排在后续阶段不等于移除已确认的首版需求。

| 阶段 | 可交付内容 | 核心验收 | 依赖 |
| --- | --- | --- | --- |
| D0 技术验证 | 最小执行器和受控网页样本 | 同会话后台／前台；两个浏览器隔离；可视化动作→Python→JS／TS→可视化动作共用状态；后台下载。 | 无 |
| D1 第一个可运行版本 | 流程 schema、顺序执行、少量通用动作、最小纵向列表、日志与下载结果 | 从界面保存并运行流程；结束后桌面存在有效下载文件，重复运行可区分结果；失败定位到步骤。 | D0 |
| D2 可自行搭建流程 | 元素拾取与元素库、变量、条件循环、脚本编辑、iframe、下拉及日期适配 | 使用演示页组合采集和下载流程，页面更新后重新定位，选择结果经过校验。 | D1 |
| D3 可靠运行 | 多任务并发、前台排队、超时取消、动作级重试、失败暂停与人工恢复 | 一任务失败不影响另一任务；恢复不重复触发已有导出；停止后监听与进程被正确清理。 | D1；与 D2 部分并行 |
| D4 定时与分发 | 日／周／月／N天计划、SQLite运行记录、补跑规则、SDK／CLI、Windows安装包 | 时间边界与停机规则通过测试；暂停期计划跳过；干净环境安装后可启动独立浏览器并运行。 | D2、D3 |

首个真实站点适配放在 D1 的通用闭环之后：由自研程序在用户完成登录后运行拼多多订单导出流程，开发时可检查定位信息，但正式流程由引擎按保存的定义执行。站点适配保存为流程模板与元素库，不把拼多多选择器写入通用执行器。

## 6. 第一批动作与建议目录

第一批动作：启动浏览器、打开页面、等待元素、点击、输入、读取文本／表格、等待匹配响应、等待并保存下载、运行 Python、运行 JS／TS、设置变量、条件、循环、结果校验。动作按里程碑逐步实现，不要求一次完成全部动作库。

建议目录（当前未创建）：

```text
apps/
  desktop/             桌面编辑器与托盘入口
  runner/              运行管理、调度、任务进程
packages/
  contracts/           流程、动作、事件与 RPC 契约
  engine/              步骤执行和变量作用域
  browser/             会话、定位、采集与下载
  picker/              元素拾取与定位规则生成
  actions/             通用指令
  sdk-js/              JS／TS 调用接口
  persistence/         SQLite 表、迁移与运行记录
python/
  rpa_sdk/             Python 调用接口
native/
  windows-helper/      输入空闲、窗口与前台管理
examples/
  pinduoduo-export/    站点流程模板和定位规则
tests/
  fixtures/            iframe、复杂下拉、分页、下载演示网站
  integration/         浏览器、脚本、暂停与调度验收
```

开发测试主要使用受控网页，明确覆盖跨域嵌套 iframe、虚拟滚动选项、延迟响应、异步导出、并发同名文件、脚本超时和重复触发。拼多多用于目标站点兼容性验证，不用于承载全部自动测试。

## 7. 建议默认值与暂缓项

为避免继续逐项访谈，可以在编码时将以下行为做成可配置项，暂采用：下载同名加序号；每月不存在的日期跳过；计划时区 Asia/Shanghai；键鼠空闲阈值可配置；对有外部效果的动作仅在确认未生效时重试。这些是开发建议，用户可修改。

暂不扩展完整桌面控件自动化、OCR、云端调度、团队权限、多网站通用智能录制。先交付用户当前需要的网页自动化能力；不承诺任何网站的所有下拉都自动适配。

当前下一项开发工作是 D0 与 D1：初始化工程、定义最小执行契约，交付能从最小桌面界面运行并保存下载结果的程序。
