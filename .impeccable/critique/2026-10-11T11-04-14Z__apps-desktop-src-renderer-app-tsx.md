**优先问题**

1. **[P1] 短窗口的日志面板几乎没有可读正文。** 在 1280×720 预览中，112px 的运行监控包含 47px 标题栏、48px 筛选栏及分隔条，日志滚动区仅剩约 8px；新的 1040×650 Electron 截图也只露出工具栏。失败原因需要先发现并拖动分隔条才能阅读。给正文保留至少两行空间；短窗口收起次要筛选，失败或等待人工时自动展开到可读高度。证据：[styles.css](C:/F/personal_RPA/apps/desktop/src/renderer/styles.css:2174)、[高度钳制](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:94)、[小窗口截图](C:/F/personal_RPA/.rpa/qa/impeccable-review/current-electron-small.png)。对应 `$impeccable adapt` / `$impeccable layout`。

2. **[P1] 切换流程后，运行控制仍指向上一流程的记录。** 浏览器观察到切到空流程或分支流程后，底部保留旧流程的失败与浏览器状态，步骤业务名称变成 `fill`。代码中 `openWorkflow` 不更新 `runId`，顶部暂停和停止使用选中运行。用户可能误认为新流程失败，或判断错控制对象；本次未实际操作停止，误控属于风险推断。默认展示当前流程最近运行；全局监控明确写出流程与运行；日志按被执行版本显示业务名称，跨流程定位先打开正确流程。证据：[切换流程](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:767)、[控制对象](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:874)、[日志名称来源](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:369)。对应 `$impeccable shape` / `$impeccable clarify`。

3. **[P1] 删除步骤或容器没有撤销。** 源码显示垃圾桶按钮直接删除；删除容器时整个子树随之移除。界面没有编辑历史或恢复入口，一次误点会丢失分支及脚本配置。应提供 Ctrl+Z/Ctrl+Y 和“已删除 N 条指令 · 撤销”；大容器提前说明影响数量，普通单条删除不必增加确认弹窗。本次未点击删除，结论来自代码路径。证据：[删除按钮](C:/F/personal_RPA/apps/desktop/src/renderer/StepTree.tsx:219)、[状态更新](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:727)。对应 `$impeccable harden`。

4. **[P2] 失败信息没有形成统一恢复路径。** 日志已有点击步骤定位功能，但用户仍需自行连接日志、参数与浏览器现场；部分全局错误直接显示 Error.message。提供失败摘要，包含流程、步骤、原因和有效下一步；按状态提供“定位步骤”“显示浏览器”，解释继续与重新运行的边界。技术错误放进展开详情。本轮未实测真实失败恢复。证据：[错误显示](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:614)、[日志关联](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:1987)。对应 `$impeccable clarify` / `$impeccable harden`。

5. **[P2] 空流程没有优先提供网页编排起点。** 中央要求从指令库选择动作，首屏却优先出现十二项桌面软件指令；网页采集用户要先找到“打开网页”，或已经知道搜索词。提供“打开网页开始”“使用订单演示”等少量起点；类别可折叠，增加网页、软件与常用切换，同时保留现有能力和真实键鼠占用说明。证据：[指令分类](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:454)、[空状态](C:/F/personal_RPA/apps/desktop/src/renderer/App.tsx:1347)、[产品共识](C:/F/personal_RPA/docs/RPA产品需求共识-2026-09-15.md:10)。对应 `$impeccable onboard` / `$impeccable distill`。

**认知负荷与角色风险**

整体负荷中等。最需要收敛的是每条步骤同时呈现的六项操作，以及切换流程后仍需记住旧运行对象。41 条指令是可搜索、分组的能力目录，不能仅凭数量认定过载；右侧四个标签和日志四类筛选职责明确。

- 新手：空流程起点不够具体，变量与元素的 JSON 配置增加门槛。
- 熟练用户：搜索和批量注释有效，缺少撤销降低快速编辑信心；长流程的每行六个按钮增加键盘焦点成本。
- 键盘与低视力用户：焦点样式和分隔条键盘调节是优点；10–12px 状态文字、运行状态播报需要后续专项检查。本轮没有 NVDA、200% 缩放或完整色彩对比度测试，不能据此宣称合规或不合规。

**情绪路径与次要观察**

本机执行、保存状态和参数说明提供掌控感；第一次添加动作与失败后的诊断是明显低谷；成功后的产物路径和打开文件入口是好的结束点。

管理和定时页仍保留所选流程的顶部保存/运行，应更清楚说明作用对象。“全部运行”的当前步骤以原始 ID 呈现，业务名称更便于扫读。等待动作显示秒而其他超时使用毫秒，可统一用户侧单位并保留内部存储格式。安全重试、暂停和键鼠占用提示值得保留。

**值得继续讨论**

- 失败时，用户能否立即看到失败位置、保留现场和可执行下一步？
- 编辑当前流程与监控所有任务，是否需要更明确的上下文边界？
- 第一次网页查询与下载，能否从任务入口开始，再逐步展开完整能力？
