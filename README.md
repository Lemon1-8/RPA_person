# Personal RPA · 本地流程工作台

按照 [RPA 开发方案 v0.1](docs/RPA开发方案-v0.1.md) 实现的首个可运行增量，覆盖 D0 技术验证与 D1 桌面下载闭环。

Electron + React + TypeScript 界面，独立 Node 任务进程，Playwright 浏览器，Python／JavaScript／TypeScript 脚本通过 RPC 共用当前浏览器。真实网站自动化由保存的流程和程序执行。

当前执行链路见 [流程执行图](docs/流程执行图.md)，涵盖单条运行、XLSX、电脑键鼠、事件传输和浏览器会话收尾，附 Archify 可编辑图源。

Windows 软件控件可在“桌面软件自动化”分类中捕获、编辑、校验和保存，通过 UI Automation 执行点击、输入、读取、勾选、选择及关联元素操作。低代码和 JS／Python 共用元素库与执行器，详见 [Windows 元素自动化](docs/Windows元素自动化.md)。

## 启动

环境：Windows、Node.js 22.13+（本机已用 24.18 验证）、Python 3.10+（执行 Python 步骤需要）。浏览器兼容处理使用 Node 内置 SQLite，因此最低 Node 版本从 22.12 提升至 22.13；不需要额外数据库服务。依赖版本由 `package-lock.json` 固定。

```powershell
npm ci
npm run setup
npm run build
npm start
```

本机依赖和 Chromium 已安装，代码也已构建，可直接运行 `npm start`，或双击根目录的 **启动工作台.cmd**。

开发模式：`npm run dev`，React 界面热更新；修改主进程／执行器后重新启动开发命令。

### 第一次使用

1. 打开内置「订单采集与导出」流程。
2. 在「运行设置」选择下载目录。默认桌面；路径须为完整绝对路径。
3. 点击「运行」。程序依次打开受控订单页面，混合执行可视化动作、Python、JS 和 TS，读取表格并保存 CSV。
4. 在右侧「运行结果 → 文件」查看实际文件，点击「打开」。重复导出同名文件自动增加序号。

默认使用本机安装的 Chrome（其次 Edge），以独立调试端口启动并连接，启动后最小化。「打开网页」会在首次使用时自动启动浏览器，在其「浏览器高级设置」中可选择浏览器和端口。「浏览器端口分配」默认选择「自动分配」，无需填写；需要固定端口时改为「手动指定」，填写 1024–65535 的整数。切回自动会清除原手动端口，旧流程中的 `debugPort: 0` 也按自动分配处理。后续复用同一浏览器，不同会话自动分配不同端口，指定端口被占用时明确报错。已有浏览器不能通过后续指令更改类型或端口。无头自动模式使用项目安装的 Chromium，适合受控测试。可在右侧运行监控显示或最小化当前任务浏览器，页面与登录状态保持在同一会话中。需要登录时可在关键步骤前暂停，显示浏览器手动操作，再继续。

**流程结束后默认保留浏览器，已有流程同样适用。** 在「运行设置 → 流程结束后的浏览器」选择「保留浏览器（默认）」或「自动关闭浏览器」。保留后可在运行记录中显示、最小化或手动关闭浏览器，也可直接关闭浏览器窗口。保留的会话继续占用浏览器配置与并发名额；整流程重跑会先关闭同流程或同配置的保留浏览器，正在取点时须先完成或取消取点。单条运行可继续复用原会话。停止任务或退出程序会清理浏览器。

关闭编辑窗口会收起到托盘，运行继续。**托盘菜单「退出并停止任务」才退出程序**。

### 单条指令运行

在编辑器上方选择「目标浏览器」，点击「运行选中指令」，或点击步骤旁的播放按钮。首次先单独运行「打开网页」，后续指令默认复用当前流程保留的浏览器，继续使用已有页面、登录状态和运行时变量；每条网页指令的「目标网页」下拉框决定该浏览器内的目标标签页。可以选择具体会话，已关闭的会话会提示重新选择。

单条运行直接使用当前编辑参数，无需保存，也不会改动已保存流程或执行前后的其他步骤。选中条件／循环／Try Catch 容器会执行其子步骤；单独执行嵌套子步骤会继承祖先的变量、元素和指令设置，但不执行祖先动作，也不会自动生成循环项或 Catch 异常变量，缺少变量时会明确报错。单条运行会保留浏览器供继续调试，同流程执行中不能同时单步操作；可通过右侧运行监控暂停、停止或关闭保留的浏览器。浏览器模式或配置名称变化后，需要关闭原会话再新建。

### 编辑与运行恢复

编辑器采用三栏布局：左侧指令库、中间流程、右侧步骤编辑或运行结果，底部只保留状态条。右栏通过「步骤编辑」「运行结果」切换；点击步骤自动显示参数，提交运行及失败或等待人工时自动显示结果。日志、运行变量、下载文件和历史记录分别位于「日志、变量、文件、历史」标签。左右栏可独立收起，右栏选择会记住；旧底栏高度设置不再占用工作区。

编辑器提供「撤销编辑」「重做编辑」，支持 `Ctrl+Z`、`Ctrl+Y` 和 `Ctrl+Shift+Z`；输入框内保留文本自身的撤销快捷键。编辑历史按流程分别保留最近 100 次编辑，关闭工作台或重新加载界面后清空。删除容器时会提示包含的指令数量，可通过「撤销删除」恢复完整子树和原先选中的步骤。保存后仍可撤销内容，下次保存会生成新的修订。

右侧「运行结果」默认只查看当前流程，切换流程时同时切换运行记录；选择「全部流程」可查看和控制其他流程的运行，监控区始终显示流程名称、运行 ID、修订和状态。顶部暂停／停止只控制当前流程的所选运行。新日志在事件中记录可选 `stepName`，复用会话后也保留发生时的名称；旧事件的名称取自该运行保存的流程快照，不随当前草稿变化。定位日志步骤会打开对应流程，已删除的步骤会明确提示。新增只读 IPC `rpa:run-workflow` 读取既有 `runs/<runId>/workflow.json`，流程 JSON v1 和历史文件格式无需迁移；缺少快照时显示步骤 ID。

失败和等待人工时，监控区集中显示原因、步骤定位与恢复操作。等待人工的「处理后继续」会用本次运行参数重试失败指令；修改草稿后应停止再重跑。终止失败或意外中断的运行须重新编辑并从头运行，也可单独运行修改过的指令。空流程可直接添加「打开网页」、使用受控网页示例，或浏览软件指令；指令库支持全部、常用、网页、软件筛选，搜索会跨类别查找。

### 指令注释

选中工作流中的指令后按 `Ctrl+/`，可注释或取消注释。按住 `Ctrl` 点击可逐条添加或取消选择，按住 `Shift` 点击可选择连续的可见指令，`Ctrl+Shift` 点击可追加一个范围，再使用同一个快捷键批量操作。混合选择时先统一注释，全部已注释时统一取消注释。快捷键只在工作流指令区生效，不干扰参数和脚本输入。

已注释指令在整流程运行时显示「已跳过」，不解析参数、不应用指令变量和设置，也不产生输出；注释容器会跳过其全部子步骤，取消容器注释后仍保留子步骤自己的注释状态。已注释指令及注释容器内的子步骤不能单独运行，需要先取消注释。

流程格式继续使用 JSON v1，每条指令增加可选 `disabled` 布尔字段。`true` 表示已注释，省略或 `false` 仍正常执行；保存、重新打开和运行快照会保留该字段，旧流程无需迁移。注释不会删除参数或子步骤。流程 JSON 的结构和动作安全配置仍需有效，取消注释后恢复原来的参数校验。

### 多网页操作

同一浏览器内，指令创建、点击弹出和手动新建的标签页都会自动登记。「目标网页」先选择「当前网页」「指定网页」或「填写名称或变量」；选择「指定网页」后，列表按已打开、流程中尚未打开、临时网页分组。选定后显示实时标题和网址，列表只查询所选浏览器，不会新建会话。

- 「打开网页」可在目标标签页跳转，或选择「新建标签页」并填写固定别名，如 `orders`、`reports`。已有标签页中的跳转保留原别名；新建时若别名已被打开的标签页占用，会明确报错。
- 「点击元素」默认在当前网页操作，也可指定目标网页。点击后不等待新标签页，不改变流程当前网页；点击产生的新标签页会自动登记，需要操作它时在后续步骤右侧选择该网页。
- 跨网页操作统一使用右侧「目标网页 → 指定网页」，只影响当前步骤，无需添加「切换网页」指令。「关闭网页」关闭指定标签页；关闭当前页后，后续步骤需指定仍打开的网页，或重新打开网页，操作不会自动落到另一页。
- 「当前网页」是流程选定的标签页，初始为 `main`，「打开网页」成功后更新为该网页。手动点击浏览器标签不会改变流程目标。空值和 `$current` 均使用当前网页；如需始终操作原主页面，请显式选 `main`。
- 元素库或指令元素带有 `pageRef` 时，目标方式中额外显示「使用元素绑定的网页」，并显示具体名称。没有元素绑定时默认显示「当前网页」。显式选择「当前网页」或固定名称会覆盖元素设置；切回元素绑定可恢复继承。
- 「打开网页」的输出包含网页名称。在「填写名称或变量」中引用它时，从变量菜单选择 `{{网页结果.pageId}}`，不要直接使用整个 `{{网页结果}}` 对象。「点击元素」只返回 `{ ok: true }`。参数类型错误会指出具体字段并提示正确引用方式。
- 手动或点击产生、尚未绑定业务别名的网页会获得 `page-2` 等自动编号，登记后可选择操作。编号仅适用于当前会话；可重复执行的流程可通过「打开网页」创建带固定别名的网页。

典型顺序：打开订单列表（`orders`）→ 打开详情网页（`detail`）→ 采集步骤目标选 `detail` → 后续点击步骤目标选 `orders`。

流程格式继续使用 JSON v1。支持 `browser.closePage`；`browser.open` 支持 `openMode`（`reuse` / `new`）、`browserChannel`、`debugPort`。「点击后切换到新标签页」已移除：旧点击步骤中的 `waitForNewPage`、`newPageId` 在加载、保存和执行时自动忽略并清除，原有点击目标和其他参数保留；原先依赖自动切页的流程需在后续步骤中指定目标网页，原先引用点击结果 `.pageId` 的地方需改用打开网页的结果。原有 `pageId` 字段保留；旧 `browser.start` 和 `browser.switchPage` 为兼容已有流程，仍可执行和编辑，但不再出现在新增指令库或添加菜单中。没有显式 `pageId` 的多页旧流程遵循元素绑定或流程当前网页；需要固定目标时请选择具体名称。

### 网页截图

在指令库「浏览器」中添加「网页截图」，选择当前或指定网页。默认截取完整网页；取消「截取完整网页」后保存当前可见区域，输出格式为 PNG。截图不会改变流程当前网页，也不需要填写元素选择器。

「保存目录」支持绝对路径和变量，留空时继承当前指令、父级或流程设置的下载目录。「文件名称」可使用变量，留空时为 `screenshot.png`，省略后缀时自动添加 `.png`；同名文件追加 `(1)`、`(2)`，不会覆盖已有文件。保存成功后登记到「下载产物」，输出变量包含 `path`、`name`、`size`、`sourceUrl`、`pageId`，后续步骤可引用 `{{截图结果.path}}`。

流程 JSON 仍为 v1，新增动作 `browser.screenshot`，参数为 `pageId?`、`fullPage?`（默认 `true`）、`directory?`、`filename?`，旧流程无需迁移。JS／TS 和 Python 脚本也可通过 `rpa.call('browser.screenshot', …)` 使用同一浏览器截图。截图超时、网页关闭或保存失败会使当前步骤报错；主动停止会中断截图。截图写文件，不支持自动重试或失败后暂停重跑。

### 智能屏蔽弹窗

「运行设置 → 智能屏蔽弹窗」提供智能（默认）、强力、关闭三种模式，旧流程未配置时默认启用智能模式。也可添加「智能屏蔽弹窗」指令，在执行过程中切换当前会话的屏蔽策略。

智能模式处理脚本对话框、无主动操作的弹出新窗，以及常见广告、营销、订阅、Cookie 弹层；持续检查动态出现的弹层，尽量保留登录、支付和业务对话框。确认框和输入提示框会取消，屏蔽器不会自动同意或提交业务操作。强力模式进一步处理通用遮罩并阻止额外弹出窗口，可能影响网站正常交互；需要弹窗的步骤前可切换为关闭。

屏蔽依赖页面结构与规则识别，无法保证覆盖所有网站。系统原生窗口、浏览器扩展窗口等不属于网页弹窗屏蔽范围，特殊网站仍可能需要针对性的关闭步骤。关闭屏蔽会恢复可恢复的页面样式；已经关闭的新窗口无法自动重开。

## 编排约定

### 变量

`{{orderNumber}}` 引用自行定义的变量；完整引用保留数字、对象、数组等原始 JSON 类型；`订单-{{orderNumber}}.csv` 将变量插入文本。

`{{orders.rows.0.0}}` 访问嵌套对象或数组。若存在名为 `order.total` 的完整变量名，`{{order.total}}` 优先读取该完整键。运行不再自动注入系统变量；运行标识与计划触发时间仅保存在运行记录中。旧流程中依赖自动注入的 `{{runId}}` 或 `{{scheduledFor}}` 引用需改为自行定义的变量或直接填写值。

新建流程和内置示例均不预置流程变量。示例地址与客户筛选直接保存在指令参数中；桌面启动时会删除已有内置示例遗留的 `demoUrl`、`customer` 默认常量，并将模板引用（包括混合文本和嵌套 JSON）替换为原值。局部变量和循环项的同名引用保留，共享元素在这些作用域中继续使用原模板。若流程已通过「设置变量」或步骤输出向同名全局变量写入，它已成为业务变量，迁移会保留初值和引用，避免改变分支和循环行为；其中仍指向原内置示例根地址的 `demoUrl` 初值会更新为当前本地端口。其它用户自定义变量保留。自定义脚本源码不会自动改写；若脚本直接读取已移除的旧默认常量，请改为字面量或自行声明需要的变量。

步骤的「输出变量」保存动作结果。日期值使用 ISO 字符串；Page／Locator 等原生对象不跨进程。

后续指令的文本和 JSON 参数旁可点「插入变量」，选择流程变量、前面步骤保存的输出或「设置变量」的值；循环内部还可选择当前项。选择后会填入 `{{变量名}}`，JSON 参数保留原始类型，文本参数在光标处插入引用。列表同时显示来源，只有分支执行或循环至少执行一次才会产生的值会标注「可能未产生」。后面的步骤、当前 if 的另一分支，以及循环外的当前项不会被列入可用变量。对象属性和数组索引可用点号继续填写，例如 `{{orders.rows.0.0}}`。

右侧「步骤参数、设置、变量、元素」均对应当前选中的指令。步骤可选的 `variables`、`elements`、`settings.downloadDir` 和 `settings.pythonExecutable` 优先于流程默认值；容器子步骤继承，兄弟步骤隔离，失败或取消后也会恢复作用域。设置变量动作或脚本 `rpa.set` 对已声明的局部变量写入当前作用域，对未声明的名称保留原有共享变量行为；显式「输出变量」在退出局部作用域后写入父级，供后续步骤使用。旧流程无需迁移，流程默认变量与元素仍可在独立「运行设置」页面编辑。

### 条件与循环

条件分支（IF）和遍历列表（FOR）以嵌套块展示，内部指令逐层缩进。每个块默认展开，空块也会显示「循环体」或「满足条件／否则」及添加入口；可直接点分支内的「添加」选择指令，或将左侧指令拖入该分支。箭头可以折叠、展开内部步骤。「结束条件／结束循环」由编辑器自动显示，无需手动添加结束指令；块之后的同级步骤在块执行完成后继续运行。

if 参数按「判断对象—比较方式—比较值」填写：例如判断对象选择变量 `item.status`，比较方式选「等于」，比较值选择文本 `已完成`。支持变量、文本、数字、布尔和高级 JSON；数字 `1` 与文本 `1` 不相等。「为真」无需比较值，`false`、`0`、空文本和 `null` 视为假，数组和对象视为真。for 可直接填写 `[1, 2, 3]`，也可选择列表变量；循环内通过 `{{item}}` 读取当前项，结束后恢复原来的同名变量。所有改动沿用现有 `children`／`elseSteps` 流程格式，旧流程可直接打开。

### 打印日志

在指令库或分支的添加菜单中选择「打印日志」，直接填写「日志内容」，也可点「插入变量」。例如在 for 的循环体内填 `当前项：{{item}}`，运行整个循环后，右侧「运行结果 → 日志」会依次显示每一项。仅填写 `{{item}}` 可直接打印该项，数字、布尔、null、对象和数组都会转成可读文本；对象和数组显示 JSON，多行文本保留换行。空字符串显示「（空文本）」。

打印日志无需浏览器或脚本环境。可在流程中使用或单独运行；循环中的 `item` 由执行循环时生成，单独运行内部的打印步骤不会生成它。引用不存在的变量会明确报错。可选的「输出变量」保存打印前的原始值，供后续步骤继续使用。

新动作使用 `core.log`，参数为 `{"message":"当前项：{{item}}"}`，沿用流程 JSON v1。日志事件通过现有日志通道保存，包含来源步骤；旧流程无需迁移。

### 等待与 Try Catch

在指令库或分支添加菜单中选择「等待」，填写「等待时长（秒）」，默认 `3` 秒，支持 `0` 到 `3600` 秒及小数，例如 `0.5` 秒。选择「使用变量」或点「插入变量」可引用数字变量，例如 `{{delaySeconds}}`；运行时变量也必须是范围内的数字。等待无需浏览器，到时继续下一条指令，点击停止可立即中断；暂停请求会在本次等待结束后生效。等待的「设置」中，步骤超时和重试间隔也以秒填写；步骤超时留空时按等待时长加 1 秒自动设置，祖先容器的超时仍会限制等待。等待某个网页元素出现时使用现有的「等待元素」。

「Try / Catch」展示「Try 执行区」与「Catch 异常区」，可在两个分支内添加、拖入或嵌套指令。先执行 Try；全部成功时跳过 Catch，失败时跳过 Try 的剩余指令并执行 Catch。Catch 成功后继续容器后的步骤。支持安全重试的失败指令先完成已配置的重试，再进入 Catch；Try 内的「失败后暂停」交由 Catch 处理。主动停止不会触发 Catch。Try Catch 容器自身或祖先容器的超时不会被当前 Catch 吞掉；Catch 再次失败会向外传播，可由外层 Try Catch 处理。

右侧「异常变量」默认是 `error`，仅在 Catch 分支内提供错误对象，包含 `message`、`stepId`、`stepName`、`actionType`。例如在 Catch 中添加「打印日志」，选择 `{{error.message}}` 查看错误信息；或添加「设置变量」，将完整 `{{error}}` 保存为业务变量供后续使用。Catch 结束后恢复原来的同名变量，没有原值时移除该变量。变量菜单会在 Catch 内提供错误及其属性，容器外不会泄漏临时异常变量。

等待可以单独运行；验证异常处理时选择整个 Try / Catch 指令运行。单独运行 Catch 内的指令不会执行 Try，也不会自动生成异常变量。

流程格式继续使用 JSON v1。等待使用 `core.wait`，参数为 `{"durationSeconds":3}` 或 `{"durationSeconds":"{{delaySeconds}}"}`，仅支持秒数参数，不兼容 `durationMs` 配置；输出为 `{"durationSeconds":3}`。异常捕获使用 `control.tryCatch`，参数为 `{"errorVariable":"error"}`，现有 `children` 保存 Try 指令，`elseSteps` 保存 Catch 指令。「结束 Try / Catch」由编辑器自动展示，无需添加结束指令。

### 彩色备注

在指令库或分支添加菜单中选择「备注」，填写多行「备注内容」。备注整行使用所选背景色，可点预设颜色、使用颜色选择器，或在「备注颜色代码」填写 `#RRGGBB`。默认是金黄色 `#FFE08A`，文字会随背景自动选择黑色或白色，选中和悬停时保留背景色。备注可复制，也可放进条件、循环和 Try Catch 分支。

备注用于说明流程，不执行操作、不打开浏览器，也不把正文打印到运行日志。正文中的 `{{literal}}` 等文字原样保留，不进行变量替换；需要输出日志时请使用「打印日志」。流程继续使用 JSON v1，备注动作是 `core.note`，例如 `{"text":"采集前检查登录状态","color":"#FFE08A"}`。

### 定时运行

先保存流程，再进入顶部「定时运行」新建计划。支持指定日期时间、每天 `HH:mm`、每 N 分钟；使用运行电脑的本地时间，触发时读取流程的最新保存版本。关闭编辑窗口至托盘仍会运行，彻底退出或电脑关机后停止；重启跳过错过的时刻，不补跑。重复计划建议将「流程结束后的浏览器」设为自动关闭，避免保留的会话占用下一次运行资源。

计划会持久化下一次触发时间、最近触发和运行标识。调度失败显示错误，不自动重试造成外部效果的流程；实际执行结果在计划列表与运行历史中查看。删除流程会同时删除其关联计划，保留历史运行；活动或保留浏览器的流程需要结束运行、关闭浏览器后删除。定时调度由桌面进程负责，CLI 查询和手动运行不会启动计划。

### 元素库与 iframe

在元素面板保存 JSON：

```json
{
  "客户输入框": {
    "pageRef": "main",
    "framePath": ["#outer-frame", "#inner-frame"],
    "selector": "#frame-input",
    "expectedCount": 1
  }
}
```

动作选择器填 `@客户输入框`。脚本也可传 `element` 对象或 `selector + framePath`。所有单元素动作要求唯一目标；重建页面后重新定位。

### 脚本

Python：

```python
from rpa_sdk import rpa
text = rpa.call("browser.text", {"selector": "#status"})
rpa.set("statusText", text)
rpa.output({"text": text})
```

JavaScript／TypeScript 支持顶层 `await`：

```typescript
const text = await rpa.call("browser.text", { selector: "#status" });
await rpa.set("statusText", text);
await rpa.output({ text });
```

脚本中的代码原样执行，通过 SDK 读取变量，不进行 `{{…}}` 文本替换。通过「Python 可执行文件」选择虚拟环境解释器。不会隐式安装用户依赖；仅运行自己信任的本地脚本。脚本进程是生命周期隔离，不是安全沙箱。更多接口见 [脚本桥说明](packages/scripts/README.md) 和 [浏览器接口](packages/browser/README.md)。

## 命令行

```powershell
# 最小化的有界面浏览器，下载到桌面
npm run demo

# 无头受控验证，自选绝对输出路径
npm run demo -- --headless --close-browser --output C:\RPA\downloads

# 运行导出的流程 JSON
npm run rpa -- run C:\RPA\workflow.json --headless --close-browser
npm run rpa -- list
```

CLI 默认使用项目 `.rpa/` 数据目录；`--data` 或 `RPA_DATA_DIR` 可覆盖。桌面默认使用系统应用数据目录，在「运行设置」可查看位置。现阶段桌面和 CLI 各自启动运行管理器，勿同时共享同一数据目录；统一常驻服务 API 属于后续交付。

CLI 同样遵循流程的浏览器保留设置；保留时命令等待用户关闭浏览器窗口或按 Ctrl+C。加 `--close-browser` 可选择结束后自动关闭，适合无头批量执行。

桌面并发可通过环境变量 `RPA_MAX_CONCURRENT` 配置为 1–16（默认 2）。浏览器配置名默认为流程 ID，可复用登录，但一个配置同时只允许一个任务占用。网站是否允许并发登录必须逐站验证。
